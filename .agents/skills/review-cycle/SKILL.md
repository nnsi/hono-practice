# レビューと修正

既存の指摘があれば、対象箇所と再現条件から対応を始める。新規レビューも依頼されている場合は指定方法を使い、指定がなければ [cross-review](../cross-review/SKILL.md)、専門分担が必要なら [multi-review](../multi-review/SKILL.md) を選ぶ。

- 指摘を実コードで確認し、依頼範囲の問題を修正する。偽陽性は理由を記録する。
- 修正した挙動と副作用を関連検証で確認する。元のレビュー担当が利用可能なら解消確認を依頼する。
- 根拠のある指摘が解消し、関連検証が通れば完了。同じ検証や全員の定型 LGTM のためだけに反復しない。
- 進展が止まったら原因に応じて調査方法を変える。ユーザー判断・外部条件が必要な残件は根拠とともに報告する。ラウンド数や編集回数だけで中断・重大度の引き下げを決めない。
