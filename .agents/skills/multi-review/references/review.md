# レビュー共通手順

- ユーザー指定の対象・比較基準を優先する。未指定なら staged / unstaged と未追跡ファイルを確認する。差分がなければ直前 commit へ勝手に切り替えず、対象なしと報告する。
- 関係する AGENTS.md と実装・呼び出し元・テストを読む。修正・formatter・有料 API・build をレビューに混ぜない。
- 具体的な発生条件、影響、コード上の根拠を示せる問題を報告する。好みだけの設計変更や根拠のない confidence 数値で採否を決めない。
- 各指摘は重大度、path:line、発生条件、影響、根拠、修正方針を簡潔に記す。確認した対象と未検証範囲を添える。
- 集約側は指摘箇所を開いて検証し、重複をまとめる。担当が失敗した場合は未実施を明記し、成功したことにしない。
- native 観点では Swift / Kotlin に加えて Expo 設定、plugin、JS bridge、共有 SQLite schema と両 OS の対応を追う。
- 報告文の監査では、結論に影響する断定を実際の証拠と照合する。根拠のない「全パス」「既存問題」「影響なし」は実証するか記述を修正する。
