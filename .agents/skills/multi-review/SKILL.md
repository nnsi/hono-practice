# 専門レビュー

[レビュー共通手順](references/review.md) に従う。ロジック、セキュリティ、設計、テストから差分に関係する観点を選び、利用可能な sub-agent に分担する。人数・同時実行数は環境の上限と差分規模に合わせる。モデルは環境の既定を使う。

- native・依存・plugin・共有 DB の変更では、両 OS と JS 境界を含む native 観点を加える。
- 報告文の監査を依頼された場合は、主張と検証結果の対応を別の観点として確認する。
- 各担当に作業ディレクトリ、比較基準、対象、担当観点、修正禁止を渡す。
- sub-agent が利用できなければ自身で観点を分け、独立レビュー未実施と明記する。
