# アカウントの自動削除

## 動作

設定のアカウント削除を確定すると、`DELETE /user/me` がそのリクエスト内で削除を実行する。日数経過を待つ cron は使わない。認証済みの本人だけが対象となり、成功時に cookie を失効させる。Web / Mobile は成功応答を確認して端末データを消し、完了を表示する。

対象はユーザー、プロバイダーの関連付け、refresh token、API キー、同意記録、活動・種類・ログ・目標・凍結期間、ノート、タスク・繰り返し設定、アカウントに紐づく問い合わせ、購読・履歴、当該ユーザーの既存アーカイブ・削除監査記録。soft delete 済みの行も含む。

画像は DB の編集可能な URL から削除先を決めず、サーバーの `icons/<userId>/` 名前空間全体を削除する。差し替えで参照がなくなった画像も含む。R2 は最大 1,000 件ずつ処理し、ローカルストレージでは symlink の削除先を拒否する。

## 失敗・競合

- ユーザー行と活動行をロックし、画像削除後に関連 DB 行を一つのトランザクションで消す。
- 画像削除や DB 操作の失敗は成功扱いにしない。DB はロールバックされるため、ログインして再試行できる。すでに削除した画像は復元されない（確認画面から参照するプライバシーポリシーに記載）。
- 削除と競合した画像アップロードは、メタデータ更新が 0 件なら失敗としてアップロードの補償削除を行う。
- 遅れて到着した購読イベントは、所有者が存在しない / 無効化済みなら無視する。削除と購読処理はユーザー行のロックで直列化する。
- 本番確認のために既存利用者を削除しない。隔離 PGlite と専用のテストアカウントで検証する。

## 別途扱うもの

- このリリース前に無効化済みのアカウントを一括削除する処理は含まない。従前に受け付けた削除依頼は個別対応する。
- ログ・バックアップ・未ログイン問い合わせ・外部サービス側の記録は、この API による即時削除の対象外。プライバシーポリシーの保存・問い合わせ方針を適用する。
- App Store / Google Play の購読は解約されない。削除前にストアで解約する。元の Actiko アカウントは復元できず、購入の別アカウント移管も行わない。
- Sign in with Apple の認可コード交換・外部トークン失効は既存認証フローに未実装。Apple ログインを使う iOS 審査前に対応・実検証が必要。今回のサーバーデータ削除だけでストア審査準備完了とは扱わない。
- Mobile の文面・完了ダイアログは JS の変更のみ。Web / API のデプロイはインストール済み Mobile の JS を更新しない。Mobile 配信時は対象 build と runtime の互換性を確認する。
