# アカウントの自動削除

## 退会時

`DELETE /user/me` は `users.deletedAt` を設定してアカウントを無効化し、refresh token と API キーを削除する。活動記録・画像・購読情報は即時削除しない。再実行しても退会日時を更新しない。Web / Mobile は成功応答後に端末データを削除し、退会完了を表示する。

## 6か月後の削除

Cloudflare Worker の scheduled handler が毎日 18:00 UTC（翌日03:00 JST）に処理する。UTCで退会日時に6暦月を加算し、その日時に達したアカウントだけが対象。月末は加算先月の末日に丸める（8月31日→翌年2月末）。未退会・6か月未満は対象外。既に退会済みのアカウントも元の退会日時で判定する。

1回最大100アカウントを古い順に処理する。ユーザー行と活動行をロックし、期限を再確認してから `icons/<userId>/` 配下の画像と関連DBデータを削除する。対象は活動・ログ・種類・目標・凍結期間、ノート、タスク・繰り返し設定、認証情報、同意記録、紐づく問い合わせ、購読・履歴、ユーザー本体。soft delete済みの行も含む。

購読履歴は既存の管理者削除と同様に `subscription_history_archive` に退避する。既存アーカイブと管理者削除監査記録は消さない。このアーカイブだけで税務上の取引記録保存が完結するとは扱わない。会計記録・外部決済記録の法定保存期間や運用は別途確認する。

## 失敗・運用確認

- ストレージ失敗・DB失敗はDBトランザクションを戻す。退会状態は維持し、次回の日次処理で再試行する。一部削除済みの画像は復元されない。
- 1件の失敗でも他の候補は処理する。件数のみログに記録し、失敗があればscheduled invocationを失敗扱いにする。CloudflareのCronイベント結果でエラーと件数を確認する。
- 成功100件で候補が残る場合は翌日以降に処理する。失敗100件が固定化した場合は原因を修正し、滞留を解消する。
- `wrangler.toml` のstg/production両環境にCronを登録する。通常のfetchルートに外部から実行できる削除バッチAPIは設けない。
- 退会後の購読イベントは既存処理で無視される。ストア購読は自動解約されない。
- 本番利用者を検証目的で削除しない。期限境界・再試行・FKを含む削除は隔離PGliteで確認する。

## 別途扱うもの

ログ・バックアップ・未ログイン問い合わせ・外部サービスの記録はこのバッチの対象外。Appleの外部トークン失効は未実装で、iOS審査前の対応が残る。Web/API配信は既存MobileのJSを更新しない。今回native変更はない。
